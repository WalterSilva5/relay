# E2 — Matriz de paridade GUI PySide → HTTP (shell Electron)

Auditoria somente-leitura de todos os acessos diretos a dados na GUI Qt,
para mapear o que o shell Electron precisará via HTTP (`local-client/relay/api/app.py`,
6432 linhas, 219 rotas `@app.*`).

- Chamadas `get_session()` em `.py` (GUI + `transcricoes/repository.py` usado pela GUI): **172**.
- Arquivos GUI com acesso direto ao banco: **17** (16 views/diálogos + `main_window.py` + `coach_widget.py`).
- `switch_db`: 1 ocorrência (somente `gui/main_window.py:1298`, troca de workspace).
- SQL cru (`s.execute`/`text()`/`SELECT` literal): **0** — tudo via ORM SQLAlchemy.
- Demais views (`chat`, `translate`, `english`, `skills`, `tools_hub`, `vault`, `guide`,
  `tech_links`, `tray`, `workspace_selector`, `meetings/*`, `settings` parcial): **0**
  `get_session`, mas várias chamam lógica de negócio **in-process** (ver tabelas).

Convenção da coluna "Endpoint existente?": ✅ coberto (método + path) · ⚠️ parcial
(existe mas com diferença de semântica/nome) · ❌ gap (endpoint a criar, coluna "Gap").

## 4. Gaps — resumo (endpoints a criar, por prioridade)

1. `GET /api/search?q=&scope=` — busca global (tasks por código/título, todos, projetos, gravações). Sem ele, a barra de busca do shell (`main_window._on_search`) não tem paridade.
2. `GET /api/dashboard` — agregados cross-project do `dashboard_view`/`metrics_view` (vencidas, hoje, semana, atividade recente). Sem ele o Electron replica N chamadas + agregação client-side (e `GET /api/tasks` pode exigir `projectId`).
3. Transcrição/áudio realtime — ou Electron implementa captura + Whisper localmente (recomendado, mantém offline), ou criar `WS /api/recordings/live/stream` + upload de áudio. É a maior decisão arquitetural do E2.
4. `POST /api/projects/{project_id}/vault/export` (`/import`) — export Obsidian hoje é escrita direta em disco.
5. `GET /api/goals/{id}/progress` (evita N+1), `PATCH /api/labels/{id}` (CRUD completo), checagens semânticas: `PATCH /api/todos/{id}` aplicar recorrência; `POST /api/http-requests/run` persistir `ApiCall`; `GET /api/vault/files` se a vault_view lista arquivos; áudio do `english_view`.

## 5. Ambiguidade / a verificar no E2

- `GET /api/tasks` exige `projectId`? Se sim, o dashboard global precisa desse param opcional ou do novo `/api/dashboard` (item 2 acima).
- `vault_view.py`: só configura o path do vault (→ `PUT /api/settings` basta) ou lista conteúdo do vault (→ precisa endpoint de arquivos)? Não auditado a fundo.
- `english_view.py`: o `tempfile`/`Path` é download de áudio TTS para playback local? Se sim, definir se o Electron toca via URL do backend ou gera local.
- `task_detail_dialog`: confirmar que `PATCH /api/tasks/{code}` grava `ActivityLog` como a GUI faz (a trilha de auditoria depende disso).
- `api_tester_view`: confirmar que `ApiRequest`/`ApiCall` (nomes no `models.py`) são as tabelas por trás de `/api/http-requests*` (possível renome semântico só na API).
- `study_view`: a GUI não grava `StudySession`; decidir se o Electron passa a logar (`POST /api/study/sessions` já existe).
